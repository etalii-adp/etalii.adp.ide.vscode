# What this plug-in supports of DISL, DESL and FBL

The plug-in reads a tool type from its definition: a DISL specification for a diagram or a DESL specification for a designer, with its FBL bindings and its companion document, copied unchanged into `definitions/<tool>/`. One interpreter (`src/core/disl/`, with what DESL adds in `src/core/desl/`), one scene (`src/core/scene/`), one table view (`src/core/tool/tableView.ts`) and one function (`toolTypeFrom` in `src/core/tool/`) turn any such folder into a tool type. This page says what they read of a definition and what they do not, which behaviours this host had to choose because a definition leaves them unstated, where a tool type here differs from its definition, and which differences are raised with `etalii.adp` and settled nowhere here.

Read it before copying a definition, to know whether it will work in this host, and when writing one, to know what this host does with a construct. A definition that asks for more than this page lists still opens: what is not supported is read as the nearest thing that is, and reported as a finding in the Problems panel.

Two other records stand beside this one and are not repeated here. [docs/parity.md](parity.md) holds the differences from the standalone modules, and [docs/fbl.md](fbl.md) holds what the FBL library implements.

## Versions

| Language | Version read | What happens with a newer minor version |
| --- | --- | --- |
| DISL | 0.12 | The specification opens, with one finding (`disl.specification`, warning) that says it is newer than the DISL this host reads |
| DESL | 0.5 | The specification opens, with one finding (`desl.specification`, warning) that says it is newer than the DESL this host reads |
| DED | 0.1 to 0.3 | A designer's document whose envelope (DED 2) names another version opens read-only, with the standalone module's reason: "This document is written in DED 0.4, and this application reads DED 0.3 and earlier. It is left exactly as it is and cannot be changed here." (DED 4, `dedRefusal` in `src/core/desl/envelope.ts`) |
| FBL | 0.1 to 0.6 | A binding of 0.7 or newer loads with a warning. See [docs/fbl.md](fbl.md) |

A specification or a binding of another major version does not load, and its folder is no tool type.

Of what DISL 0.5 to 0.12 add, these constructs are not built yet, and a definition that uses one opens without it: the `person` shape of 0.5, a view's `scope` and `location()` of 0.7, `self.view.groups` and `std.notAValue` of 0.11, *(spec 089)* 0.12's action `lookup` (DISL 9.4): without a pick the operation is answered with the host's lookup, and run again with the element picked, which creates an element of `create` whose link attribute is the pick's link and whose label attribute its name, as the last child of `self`, or at the point with `as: "at"`; `origins` narrows the lookup to the documents of those tool types. A field with the widget `lookup` shows its link by the target's current name while it resolves, else the name it caches, and is read-only with the sentence that says how a link is chosen and opened. 0.12's `linkable`, `linked` and `persistence.documentId` are read (`src/core/disl/links.ts`): a document of a type whose persistence declares a document id is indexed with its id, its elements of linkable types named by their `nameProperty` (by default their label attribute) and the links its attributes of type `link` hold (`ToolType.indexed`). Given the workspace's index (`Source.links`), its links are resolved (FBL 17.3): a linked element is labelled with its target's current name and `self.linked` holds the target's `shows` attributes, absent while the link does not resolve; a link that does not resolve is reported at the element that holds it (`link.malformed`, an error, and `link.broken-document`, `link.broken-element` and `link.ambiguous-document`, warnings, with their candidates); and the first edit of the document writes, in the same step, what load-time validation finds (FBL 17.4): a document id where the body holds none, and each link whose text differs from what resolution found, with the label attribute that caches the target's name. Without the index, a link is shown as written and not checked. An attribute of type `link` is read as a string. 0.12's `nanoid` ids with `alphabet` and `length` are made as DISL 11.5 says, and a form field's `readOnlyReasons` apply while its own `readOnly`, when it states one, holds, as the desktop host reads them. *(spec 090)* A derived node type of 0.8 (DISL 4.11.2) is read: one node for each distinct `key` of what its `from` gives, with its `id`, `attributes` and `sources`, drawn and listed in ADP Properties as read-only with its `reason`, its gestures refused with that reason, and a stored relation's end may name it. 0.6's relation flags and 0.10's `persistence.writtenId` are read; 0.9's `groupBy` is the feature `cel.groupBy`, which a definition that uses it requires and which this host does not list, so such a definition opens with `disl.unsupported-feature`.

## Conformance class and features

The list is the one of [`src/core/disl/support.ts`](../src/core/disl/support.ts): a feature is added there by the change that builds it, and to this table with it. A test holds the two together. A specification whose `language.requires` names another feature, or a higher conformance class, opens with one finding for each (`disl.unsupported-feature`, `disl.unsupported-conformance`, both warnings).

The conformance class is `standard`.

| Feature | What is built |
| --- | --- |
| `axis.time` | *(spec 091)* A time axis of dates and times (`valueType: datetime`, DISL 5.4): a date or a date and time in ISO 8601 placed at its days since the axis's origin, a time of day as a fraction, with a unit of fixed length from a millisecond to a week |
| `axis.yearMonth` | A time axis whose values are a year and a month, counted in months, with a unit of a month or coarser that may be bound to an attribute of the diagram |
| `ruler.adaptive` | A ruler whose levels are shown by the room their labels have on screen (`minSpacingPx`, `minZoom`, `maxZoom`, `step`), never finer than `minUnit` |
| `snap.byGesture` | Snapping rules per gesture, read with the coordinate system and the node notation |
| `snap.calendar` | *(spec 091)* A calendar snap rule (DISL 5.10) on a time axis of dates: a position or a dragged edge on a whole number of days from the origin, or of months on an axis of months, `align` choosing the start of the unit, its end or the nearer. A date is written as a date and a date and time in whole seconds, as the value it replaces was written |
| `anchor.part` | An edge end on a part of a composite shape, on a side of it and a fraction along that side |
| `anchor.sides` | An edge end at the middle of one of the sides of its node that the notation names, the one nearest the other end |
| `canvas.filters` | The filters of `notation.canvas.filters` with the controls `chips`, `switch`, `select` and `search`, the effects `hide` and `dim`, and matching any or all |
| `viewpoint.variants` | A viewpoint that varies another, offered as its `toggle` |
| `placement.bound` | A node placed by its attributes on both axes, with `x2`, `y2`, `width`, `height`, `offset` and an anchor |
| `shape.custom` | A shape declared as path segments with parameters and handles |
| `shape.composite` | A shape made of parts, each with its own shape, box, style, condition and tooltip |
| `edge.bezier` | An edge drawn as a cubic curve, with `startDirection`, `endDirection`, `reach` and `maxReach` |
| `label.parse` | A label whose edited text is parsed and written by the specification's own rule |
| `label.editText` | A label whose editor in place starts from a text of its own rather than the text drawn |
| `persistence.fbl` | A document read and written through an FBL binding |
| `persist.typeMap` | The binding's own type and attribute names mapped onto the metamodel, a reference attribute of the binding read as a relation's end |
| `view.viewer` | Viewer state that is a fold: `persistence.view.viewer` with `collapsed`, seeded by `view.initial`, read as `self.view.collapsed`, changed by a `view` action, kept per open editor and never written |
| `canvas.chrome` | *(spec 081)* The empty message of `canvas.empty`, drawn while its `when` holds as plain text centred on the surface in the size and colour of its `style`, and the legend from its declared entries. The title and the header are not drawn, as DISL 15.2 lets a runtime without them degrade |
| `form.parse` | *(spec 081)* A row whose typed text is parsed by its own `parse`: `accepts`, `write` with `set` and `unset` under `when`, and `refusal`, worded in the input box as it is typed |
| `form.rowId` | *(spec 081)* A row's own `id`, which names it to the properties view and to an edit, before its attribute's name |
| `constraints.order` | *(spec 081)* Findings ordered by the order of their codes that `constraints.order` lists, then by line, a group of duplicates by its first member |

DISL 0.4 names no feature identifier for what it adds (its Appendix B.8 ends at 0.3, see issue [159](https://github.com/etalii-adp/etalii.adp/issues/159)), so a specification cannot require those constructs by name and this table cannot list them. What is read of them is in the next section: grouped compartments with an item order and item links, a kept filter, `pin`, `unpin` and `unpinAll`, the `open` action, the `force` layout in tiers, `paths` on a `uri` attribute and `persistence.view.bind`.

An object a reference names and the file does not hold is drawn as a placeholder of the derived node type `Missing`, dashed and read-only; a data source is a cylinder; the lines of a reference are routed with rounded corners. An objective's target and the SLO's window are changed in ADP Properties as the bytes of FBL's `openslo-slo-edits` say, and every file those steps write passes `oslo validate` (oslo 0.13.0). A registration that names no document of its own and stands in a folder of OpenSLO files opens that folder (FBL 10), through the binding of the definition's FBL document that claims the tool type's origin for a registration alone: the files its file rules select are read once, when it opens, and drawn read-only, a reference from one file to an object of another drawn in full. Ids are each type's own `ids.types` expression (DISL 11.5.2), read in two passes so that `self.parent` and `positionIn` see the elements read. ### Post-incident review designer

The post-incident review designer is read from its definition alone (etalii.adp spec 090): it names no plugin. Its two examples are read as FBL's fixtures `post-incident-review-read` declare, every entry, factor, action and category with its attributes, lists of evidence and references included, and its milestones and the four intervals between them are computed from its functions. Its surface is of the kind `sections` (DESL 0.4, 7.8), drawn as a page of its six parts: the summary and the impact as forms of the document's fields with the four intervals beside the summary's title, the timeline in time order with its time strip, the factors under their categories, the actions and the categories, each row with its marks, its findings, its operations as buttons and its fields to type in, and the rows a selected one mentions, and that mention it, highlighted. Accept, reject, complete and every add gesture are each one edit and one undo step, and so is a field given a value, as the bytes of FBL's fixture `post-incident-review-edits` say.
